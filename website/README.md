# Pragmatic JMeter docs site

A searchable docs site built with [Docusaurus](https://docusaurus.io/) and
[local search](https://github.com/easyops-cn/docusaurus-search-local) (no external service).
It is published to GitHub Pages at
<https://pragmatictesters.github.io/Pragmatic-JMeter-Training/>.

## Where the content comes from

| Site section | Source | How it gets here |
|---|---|---|
| Tip of the Day, Testing Types, Glossary | `../docs/*.md` | Copied by `scripts/sync-docs.mjs` before every `npm start` / `npm run build`. **Edit the files in `../docs`.** |
| Welcome page | `docs/intro.md` | Edit directly. |
| Reference (components, functions, properties, jmeter.properties) | Your local JMeter install (`printable_docs/usermanual/*.html`, `bin/jmeter.properties`) | Generated by `scripts/generate-reference.mjs` and committed, so CI does not need JMeter. |

## Run it locally

Needs Node.js 20 or newer.

```bash
cd website
npm install
npm start
```

Search only works in a production build:

```bash
npm run build
npm run serve
```

## Regenerate the JMeter reference

After upgrading JMeter, point the generator at the new install and commit the result:

```bash
JMETER_HOME=/path/to/apache-jmeter-5.6.3 npm run generate:reference
```

Without `JMETER_HOME` it uses the newest `apache-jmeter-*` folder in the repository root.

## Deploy

`.github/workflows/deploy-docs.yml` builds and deploys on every push to `main` that touches
`docs/` or `website/`. One-time setup: in the GitHub repo go to
**Settings → Pages → Build and deployment** and set **Source** to **GitHub Actions**.
